# 07 · M5 第二课：轻量训练建立「格式专属表示」方向（2026-11-20）

承接 `docs/06_m5_formats.md`。第一课只立了**接口形状**：`cos(clf,rgn)=0.9992`，
两个格式几乎不可分 —— 因为 `[unused0]/[unused1]` 两行 embedding 从未被训练，
控制码只是个「位置标记」。本课用**极轻量的训练**把因果补上：不训练 BERT 主体，
只让两行控制码 + 两个小头可训，观测 `cos(clf,rgn)` 是否下降。

复现粒度仍是「结构 + 方向对齐」，**不刷分、不追论文效果**。

## 1. 因果链（本课真正要掌握的）

```
clf 路: 插 id=2 -> emb 查 W[2] -> h[:,1] -> head_clf -> 19 类交叉熵 -> 梯度只回 W[2]
rgn 路: 插 id=3 -> emb 查 W[3] -> h[:,1] -> head_rgn -> 引用数 MSE -> 梯度只回 W[3]
```

embedding 查表只有**被命中的那一行**有梯度，所以两行天然被不同任务信号推，
方向必然不同。这就是「格式专属表示必须来自训练」从推断变成实测的机制：
第一课的 `0.9992` 不是接口写错了，而是**缺了梯度**。

梯度 mask（`g.assign(g * keep_j)`）的作用常被讲反：它不是「让 row2/3 有梯度」
（查表命中本来就有），而是**阻止 title/abstract 那些文本 token 的 embedding 行被一起更新**。
少了这步，整张词表被拖动，实验就不干净。

## 2. Jittor 契约：训练态绝不调 `eval()`（2026-11-19 抓到的真 bug）

4-case 诊断（`_m5_diag2.py`）：

| case | `eval()` | W2/W3 梯度 | W 变化 |
|---|---|---|---|
| A / B | ✅ | `[0, 0]` | `[0, 0]` |
| C / D | ❌ | `[0.21/0.28, 0]` | `[0.01, 0]` |

PyTorch 里 `eval()` 只切 dropout/BN，`requires_grad` 不动；**Jittor 的 `eval()`
会连参数一起 `stop_grad`**。参照脚本第一版照抄 `encoder.py` 的 `self.model.eval()`，
结果 head 的 loss 还在跳（head 可训），控制码两行却完全冻结、`cos` 纹丝不动 ——
**静默失败**，最难查的一类。

修复不是「加 `train()`」，而是**根本不调 `eval()`**；主体冻结改由
「不把它们的参数放进 optimizer」实现。由此形成仓库契约：

> `PaperEncoder` 是推理类（`__init__` 里 `eval()` + `encode` 里 `no_grad()`），
> 可以 eval；**训练态一律不 eval**。凡从 PyTorch 习惯迁过来的训练代码，
> 必须单独验一次「目标参数是否真的变了」，不能只看 loss。

## 3. 数据与配置

| 项 | 值 |
|---|---|
| 监督集 | `data/training/fmt_train.jsonl`，512 篇，来自 SciDocs MAG/MeSH 同一批论文 |
| CLF 标签 | `mag/train.csv` 的 `class_label`，映射成 0-based 19 类，交叉熵 |
| RGN 目标 | `paper_metadata_mag_mesh.json` 的 `cited_by`（list）取 `len()`，0~948 长尾 → `log1p` + 标准化，MSE |
| 控制码 | `clf=2` / `rgn=3`（`[unused0]/[unused1]`），与 `encoder.py:13` 一致 |
| 可训参数 | `word_embeddings.weight` 的 row2/row3 + `head_clf`(768→19) + `head_rgn`(768→1) |
| 冻结 | 12 层 Transformer 全部 198 张量（不进 optimizer）；`weight_decay=0` 排除隐性衰减 |
| 配置 | 60 步、batch 8、`lr=3e-2`、`max_len=96`、`SEED=42`（numpy 采样） |

脚本：`scripts/16_train_fmt.py`（用户手打），产物 `models/scibert/scibert-fmt.npz`。

## 4. 实测结果（真实权重，非合成）

```
[init]   cos(W2,W3) = 0.6748
[10/60]  cos(W2,W3) = -0.1364        [40/60] -0.1016
[20/60]  cos(W2,W3) = -0.1569        [50/60] -0.0836
[30/60]  cos(W2,W3) = -0.1260        [60/60] -0.0692
[final]  cos(W2,W3) 0.6748 -> -0.0692   dW2=0.7725  dW3=0.6233
[verify] cos(None,clf)=0.5551  cos(None,rgn)=0.5415
[verify] cos(clf,rgn) = 0.6319   (基线 0.9992, 期望明显下降)
[time]   247.4s total
```

**结论**：`cos(clf,rgn) 0.9992 → 0.6319`，格式专属表示的**方向建立**。
F1 闸进一步自证「冻结主体」：`scibert-fmt.npz` 对基线只有
`embeddings.word_embeddings.weight` 一个张量变化，且变化行恰为 `[2, 3]`，
其余 198 张量逐位相等，全表 finite。

### 关于 `cos(W2,W3)` 的负数

`cosine` 值域是 `[-1, 1]`，负数是**合法值**，表示两行控制码 embedding 被推过
90°（略反向）。要区分两个量：

| 量 | 层次 | 基线 → 训后 |
|---|---|---|
| `cos(W2,W3)` | 词表里两行**参数向量** | `0.6748 → -0.0692`（解耦，越接近 0 越彻底） |
| `cos(clf,rgn)` | 12 层 Transformer 后的**文档表示** | `0.9992 → 0.6319`（仍为正，这是判据） |

真正该警惕的是 **cos > 1**（M1 早期检验器分母括号丢失跑出 14401，那是检验器坏了）。
参照版跑出 `+0.0733`、手打版 `-0.0692`，两者都≈正交，方向一致。

## 5. 诚实边界（必须随结果一起汇报）

1. **不是 SPECTER2 的 pre-finetune**：原文是 8 个数据集、几十万级三元组、
   多任务 pre-fine-tune + Adapter Fusion。这里 512 篇、60 步、只训两行，
   loss 全程波动（`loss_c` 2.7~6.2、`loss_r` 3.1~10.0）**不收敛是正常的** ——
   观测目标是 `cos` 下降（因果成立），不是下游分数。
2. **不宣称格式内 > 共享 `[CLS]`**：只证「两格式可分」，未跑任何下游评测。
3. **范数膨胀**：W2/W3 范数从基线行均值 ~1.08 涨到 `6.896 / 6.036`（~6 倍）。
   cosine 与模长无关，不污染判据；但控制码信号确实被放大，如实记录。
4. **可复现性**：`SEED=42` 只固定 numpy 的 batch 采样，未固定 Jittor 里
   `head_clf/head_rgn` 的随机初始化，所以两次运行 loss 轨迹与落点有差异
   （`+0.0733` vs `-0.0692`）。轻量纪律下不追逐位可复现。
5. **口径**：本课训练/验证用 `max_len=96`（提速），与 M2 训练 256、评测 512 不同；
   它只产出 M5 的控制码权重，不参与 `02/03/05` 任何归档数字。
   A 闸确认 `fmt=None` 逐位 `cos=1.0 / max_abs=0`，归档数字一个没动。
